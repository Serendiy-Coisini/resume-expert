## 不可破坏的边界

- 修改用户维护的源文件，不直接修补 `public` 下压缩 JS、source map 或其他生成产物。
- 每个源文件在第一次实质性修改前创建唯一备份；后续再次进行实质性重写时也要按适用规则备份，禁止覆盖旧备份。备份放到非发布目录，避免被编译器重复纳入，记录位置。
- 根工程使用 npm；`resume-design-main` 子工程使用 pnpm。不要混用或无依据升级依赖。
- 保留 Mock 演示链路、已存在的 HTML 清洗、SSRF 防护、文件限制、解析隔离和取消机制。
- 不要通过放开任意 HTML、SVG、外链或脚本来解决打印问题。
- 不得编造用户简历事实，不得把新内容写进错误组件，不得因切换模板或恢复备份静默删除文本。
- 高度和分页算法必须先补实际回归样例，再修改；不要只调几个经验常数来掩盖截断。
- 不要一次性重写整个编辑器，也不要引入数据库、编辑器框架或复杂状态库作为默认方案。
- 一般实现选择自行判断。只有真实阻塞、不可逆操作或超出上述授权时才需要澄清；继续完成不受影响的工作。

### 第一阶段：数据与导入边界（P1）

#### R01 Schema 无损往返

- 定位：`schema-normalizer.ts`、`lego-designer-store.ts`。
- 内部 `setSchema()` 不应进行有损的外部格式转换。外部导入需要校验和版本迁移，内部更新需要维持类型与不变量。
- 保留合法页面边距、组件透明度（包括 0）、下划线、阴影及其他受支持属性。不要无条件传播未知危险字段。
- 验收：编辑 → 保存草稿/模板/JSON → 恢复后，所有受支持属性和内容等价；重复标准化不再持续改变尺寸或内容；旧格式可迁移。

#### R02 JSON 和组件运行时校验

- 定位：`ImportResumeDialog.tsx`、`Toolbar.tsx`、`schema-normalizer.ts`、`types/lego.ts`、`WidgetRenderer.tsx`。
- 对 FinalResume 和组件使用实际运行时校验，优先复用 Zod。建立组件类型与数据结构的明确对应。
- 约束文件大小、页数、组件数、文本长度、数值范围、评分上限；拒绝或明确修复重复 ID、非法数据、超大参数。
- 明确列表对象项的兼容策略，避免仅用类型断言绕过。
- 验收：`{}`、错误数组、对象列表项、重复 ID、极大尺寸和 maxRate 均不会白屏或无界循环；失败不覆盖现有画布。

#### R03 导入事务与取消语义

- 定位：`ImportResumeDialog.tsx`、`resume-store.ts`。
- 预览、解析、选择预设和编辑表单只更新弹窗本地草稿。构建与校验成功后才提交全局简历和画布。
- 取消不改变原简历、分析结果、会话、步骤或画布；上传任务过期、关闭弹窗后不能回写。
- 不要把上一份简历的 JD 匹配分数和诊断强行拼进新简历并标记为有效分析。
- 验收：取消、失败、重复上传、切换预设、手动编辑与上传竞态均有覆盖。

#### R04 完整备份恢复与仅套用版式分离

- 定位：`Toolbar.tsx` 的 JSON 导入及 `fillAiDataIntoExistingSchema()`。
- 完整备份恢复默认原样保留文本；只有明确选择套用版式时才用当前简历重填。
- 先校验迁移，再重填；不能因未识别旧格式而静默生成默认简历。
- 验收：在另一份简历上下文中恢复备份，姓名和经历仍为备份内容；版式导入需有明确入口与反馈。

### 第二阶段：编辑状态与内容绑定（P1）

#### R05 选中状态不变量

- 定位：Store 新增、复制、删除、撤销、重做与批量操作。
- 单选/主选中项与选中集合必须一致；每次文档变化后移除不存在的选中 ID。
- 验收：复制 A 后属性编辑、方向键和 Delete 均作用于副本；删除和撤销后无残留选中项。

#### R06 来源版本与头像同步

- 定位：`getResumeSourceKey()`、`LegoDesigner`、照片上传和删除。
- 用稳定文档身份和内容版本区分真正跨简历变化；普通图片编辑不应触发要求丢弃手工排版的过期拦截。
- 画布、关联内容和来源版本应在同一逻辑提交内保持一致。
- 验收：无分析结果的独立编辑器上传/删除照片可继续编辑；真实切换简历仍有正确保护。

#### R07 重填必须使用语义绑定

- 定位：`lego-adapter.ts`。
- 修复 grid-cards 背景误匹配。逐步为模板组件建立 binding、section/item/group 等稳定字段，不依赖标题或 ID 子串长期猜测。
- 旧模板可使用受控迁移；无法可靠识别时应保留并提示，不能猜测后破坏内容。
- 验收：所有内置模板在经历增加、减少、为空及工作/项目并存时，内容进入正确位置，装饰背景不变为正文，超出的旧事实不残留。

#### R08 手工正文、模板切换与导出内容一致

- 定位：`RightSetter.tsx`、`Toolbar.tsx`、`export-step.tsx`。
- 明确内容唯一来源或同步契约。模板切换不能声称保留文本却重新使用旧分析结果。
- 自由文本组件无法反推结构化简历时，必须提供明确保留策略与提示，不要求做不可靠的万能逆转换。
- 标准视图与画布视图的导出来源应明确。Word 保持结构化可编辑内容版，不要求映射绝对坐标。
- 验收：改正文后换模板、切换视图、导出 PDF/Word，行为符合明确契约且不会静默丢字或使用旧内容。

#### R09 撤销重做按用户操作提交

- 定位：Canvas、右侧主题控件、Toolbar、Store。
- 点击不创建历史，不清空重做。拖动/调色开始记录基线，预览不入栈，完成且有变化时提交一次。
- 合并连续输入与连续方向键的合理操作单元；避免 pointer/mouse/touch 重复提交；清理未执行的 RAF。
- 验收：点击保留 redo；一次拖动/调色一次撤销即可恢复；新实质编辑正确清空 redo；历史容量有界。

#### R10 Pointer 与多页坐标

- 定位：`LegoCanvas.tsx`。
- 使用 Pointer Events 与 pointer capture 等可靠机制，处理 pointerup、cancel、失焦和组件卸载。
- 每页独立引用和 pageId；框选、吸附、拖动坐标限定所在页。避免重复 DOM ID。
- 验收：画布外松开不粘住；缩放后拖动准确；第二页框选不误选第一页；触摸及 Shift 多选行为正确。

### 第三阶段：排版与打印（P1）

#### R11 明确页面模型与 PDF 完整性

- 定位：`printLego.ts`、`LegoCanvas.tsx`、分页模块。
- 统一长画布分片与 componentsTree 多页的关系，支持已有数据迁移。打印不能只取第一 DOM 页。
- 分片按实际边界向上取整，缩放使用实际宽度，避免尾部丢失和多余空白页。
- 验收：1160px、1400px、2320px、高度略超整页、自定义宽度、两个真实页面均完整输出。打印内容包括所有页面且顺序正确。

#### R12 可信打印资源与图标

- 定位：`printLego.ts`、`safe-html.ts`、WidgetRenderer。
- 保留用户内容清洗；由应用提供可信打印 CSS 与受控图标，不能简单放行任意 SVG 或外链。
- 避免依赖被 sanitizer 删除的 link。避免打印统一 cover 样式裁剪二维码等应 contain 的图片。
- 资源等待设置上限；使用完成事件与兜底清理，不仅依赖固定延时。
- 验收：生产样式环境中图标、字体、列表、二维码与背景正确；恶意富文本不执行；加载失败有反馈且无 iframe 泄漏。

#### R13 实际高度与分页策略

- 定位：`lego-adapter.ts`、WidgetRenderer、属性更新命令。
- 先建立基准样例，再统一测量与渲染参数。编辑文本、宽度、字号、行高后更新尺寸与画布边界。
- 为超单页卡片定义拆分或明确溢出处理；不能只向后挪一页。
- 验收：中文、英文、混排、换行、富文本、大字号、窄栏、长经历、标题孤行、跨页组均覆盖；无正文重叠、截断和无限重排。
